TypeScript 6.0 改变了类型定义的发现方式。如果你升级了 TypeScript,编辑器不再识别来自 `@types/bun` 的 `Bun`、`Request` 或其他全局对象,可以按下面的方法修复。

## 变了什么

从 TypeScript 6.0 开始,`compilerOptions` 中的 `types` 字段默认为空数组,不再包含所有 `@types/*` 包。现在需要显式列出你使用的类型包。

## 在 tsconfig 中加入 `"types": ["bun"]`

在 `tsconfig.json` 的 `compilerOptions` 中加入 `"types": ["bun"]`:

```jsonc tsconfig.json icon="file-json"
{
  "compilerOptions": {
    "types": ["bun"], // [!code ++]
  },
}
```

`types` 数组告诉 TypeScript 从 `@types/bun` 加载类型定义。如果你还使用其他 `@types/*` 包,也一并列入:

```jsonc tsconfig.json icon="file-json"
{
  "compilerOptions": {
    "types": ["bun", "react"],
  },
}
```

仍然需要安装 `@types/bun`。`types` 选项只是告诉 TypeScript _包含哪些_包,但包本身必须存在于 `node_modules` 中:

```sh terminal icon="terminal"
bun add -d @types/bun
```

## 完整推荐的 tsconfig.json

以下是使用 TypeScript 6.0 及以上版本的 Bun 项目的完整推荐 `tsconfig.json`:

```jsonc tsconfig.json icon="file-json"
{
  "compilerOptions": {
    // Environment setup & latest features
    "lib": ["ESNext"],
    "target": "ESNext",
    "module": "Preserve",
    "moduleDetection": "force",
    "jsx": "react-jsx",
    "allowJs": true,
    "types": ["bun"],

    // Bundler mode
    "moduleResolution": "bundler",
    "allowImportingTsExtensions": true,
    "verbatimModuleSyntax": true,
    "noEmit": true,

    // Best practices
    "strict": true,
    "skipLibCheck": true,
    "noFallthroughCasesInSwitch": true,
    "noUncheckedIndexedAccess": true,
    "noImplicitOverride": true,

    // Some stricter flags (disabled by default)
    "noUnusedLocals": false,
    "noUnusedParameters": false,
    "noPropertyAccessFromIndexSignature": false,
  },
}
```

## TypeScript 7 也适用吗?

适用。TypeScript 7 延续了同样的默认行为。如果你从 TypeScript 5 直接升级到 7,修复方法相同——在 `compilerOptions` 中加入 `"types": ["bun"]`。
