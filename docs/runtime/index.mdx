Bun 运行时的设计目标是启动快、运行快。

Bun 使用 [JavaScriptCore 引擎](https://developer.apple.com/documentation/javascriptcore),即 Apple 为 Safari 开发的引擎。JavaScriptCore 的启动和运行速度通常快于 V8(Node.js 和 Chromium 系浏览器使用的引擎)。Bun 的转译器和运行时用 Rust 编写。在 Linux 上,Bun 的启动速度比 Node.js [快 4 倍](https://twitter.com/jarredsumner/status/1499225725492076544)。

| 命令            | 耗时     |
| --------------- | -------- |
| `bun hello.js`  | `5.2ms`  |
| `node hello.js` | `25.1ms` |

该基准测试在 Linux 上运行一个 Hello World 脚本。

## 运行文件

使用 `bun run` 执行源文件。

```bash terminal icon="terminal"
bun run index.js
```

Bun 无需任何配置即可支持 TypeScript 和 JSX。Bun 在运行每个文件之前,会用原生的[转译器](/runtime/transpiler)即时转译。

```bash terminal icon="terminal"
bun run index.js
bun run index.jsx
bun run index.ts
bun run index.tsx
```

也可以省略 `run` 关键字,直接使用"裸"命令,行为完全一致。

```bash terminal icon="terminal"
bun index.tsx
bun index.js
```

### `--watch`

要以 watch 模式运行文件,使用 `--watch` 参数。

```bash terminal icon="terminal"
bun --watch run index.tsx
```

<Note>
使用 `bun run` 时,应把 `--watch` 等 Bun 参数紧跟在 `bun` 后面。

```bash
bun --watch run dev # ✔️ do this
bun run dev --watch # ❌ don't do this
```

`bun` 会忽略命令末尾的参数,并把它们透传给 `"dev"` 脚本本身。

</Note>

## 运行 `package.json` 脚本

<Note>
对应 `npm run <script>` 或 `yarn <script>`
</Note>

```sh
bun [bun flags] run <script> [script flags]
```

`package.json` 可以定义与 shell 命令对应的具名 `"scripts"`。

```json package.json icon="file-json"
{
  // ... other fields
  "scripts": {
    "clean": "rm -rf dist && echo 'Done.'",
    "dev": "bun server.ts"
  }
}
```

使用 `bun run <script>` 执行这些脚本。

```bash terminal icon="terminal"
bun run clean
rm -rf dist && echo 'Done.'
```

```txt
Done.
```

Bun 在子 shell 中执行脚本命令。在 Linux 和 macOS 上,它按以下顺序检查可用的 shell,并使用找到的第一个:`bash`、`sh`、`zsh`。在 Windows 上,它使用 [Bun Shell](/runtime/shell) 来支持类 bash 语法和许多常用命令。

<Note>⚡️ Linux 上 `npm run` 的启动开销约 170ms;Bun 只要 `6ms`。</Note>

也可以用更短的命令 `bun <script>` 运行脚本。如果与内置 `bun` 命令重名,内置命令优先;此时请用显式的 `bun run <script>` 来运行你的 package 脚本。

```bash terminal icon="terminal"
bun run dev
```

不带参数运行 `bun run` 可以查看可用脚本列表。

```bash terminal icon="terminal"
bun run
```

```txt
...
package.json scripts (2 found):
  $ bun run clean
    rm -rf dist && echo 'Done.'

  $ bun run dev
    bun server.ts
```

Bun 支持生命周期钩子。例如 `bun run clean` 会依次运行 `preclean` 和 `postclean`(如果定义了)。若 `pre<script>` 失败,Bun 不会运行脚本本身。

### `--bun`

`package.json` 脚本引用本地安装的 CLI(如 `vite` 或 `next`)很常见。这些 CLI 通常是带有 [shebang](<https://en.wikipedia.org/wiki/Shebang_(Unix)>) 的 JavaScript 文件,声明用 `node` 执行。

```js cli.js icon="/icons/javascript.svg"
#!/usr/bin/env node

// do stuff
```

默认情况下,Bun 遵循该 shebang 并用 `node` 执行脚本。`--bun` 参数可以覆盖它:CLI 将用 Bun 而不是 Node.js 运行。

```bash terminal icon="terminal"
bun run --bun vite
```

### 过滤

在 monorepo 中,`--filter` 参数可以一次在多个包中运行脚本。

`bun run --filter <pattern> <script>` 会在 `<pattern>` 选中的每个包中执行 `<script>`。模式可以是包名 glob、`./path`、`{dir}` 目录,或 `foo...` 这样的依赖关系表达式。
例如,假设你有包含名为 `foo`、`bar`、`baz` 的包的子目录,运行

```bash terminal icon="terminal"
bun run --filter 'ba*' <script>
```

会在 `bar` 和 `baz` 中执行 `<script>`,但不会在 `foo` 中执行。

参见 [`--filter`](/pm/filter#running-scripts-with-filter)。

## 用 `bun run -` 从 stdin 管入代码

`bun run -` 从 stdin 读取 JavaScript、TypeScript、TSX 或 JSX 并执行,不先写入临时文件。

```bash terminal icon="terminal"
echo "console.log('Hello')" | bun run -
```

```txt
Hello
```

也可以用 `bun run -` 把文件重定向给 Bun。例如,把 `.js` 文件当 `.ts` 文件运行:

```bash terminal icon="terminal"
echo "console.log!('This is TypeScript!' as any)" > secretly-typescript.js
bun run - < secretly-typescript.js
```

```txt
This is TypeScript!
```

`bun run -` 把所有输入视为支持 JSX 的 TypeScript。

## `bun run --console-depth`

使用 `--console-depth` 参数控制 console 输出中对象检查的深度。

```bash terminal icon="terminal"
bun --console-depth 5 run index.tsx
```

`--console-depth` 设置 Bun 在 `console.log()` 输出中显示嵌套对象的深度。默认深度为 `2`。数值越高,显示的嵌套属性越多,但对复杂对象可能产生冗长的输出。

```ts console.ts icon="/icons/typescript.svg"
const nested = { a: { b: { c: { d: "deep" } } } };
console.log(nested);
// With --console-depth 2 (default): { a: { b: { c: [Object] } } }
// With --console-depth 4: { a: { b: { c: { d: 'deep' } } } }
```

## `bun run --smol`

在内存受限的环境中,使用 `--smol` 参数以牺牲性能为代价降低内存占用。

```bash terminal icon="terminal"
bun --smol run index.tsx
```

`--smol` 会让垃圾回收器更频繁地运行,可能拖慢执行速度。无论是否使用 `--smol`,Bun 都会根据可用内存(考虑 cgroup 等内存限制)调整垃圾回收器的堆大小。因此该参数主要在希望堆增长得更慢时有用。

## 解析顺序

Bun 总是把绝对路径和以 `./` 或 `.\\` 开头的路径当作源文件执行。除非使用 `bun run`,否则带允许扩展名的名字会被解析为文件而不是 `package.json` 脚本。

当 `package.json` 脚本与文件同名时,`bun run` 优先选择脚本。完整的解析顺序为:

1. `package.json` 脚本:`bun run build`
2. 源文件:`bun run src/main.js`
3. 项目包中的二进制:`bun add eslint && bun run eslint`
4. (仅 `bun run`)系统命令:`bun run ls`
